# Native TSL constraint editing: prior art and experiment boundary

Primary-source audit checked on 2026-09-09. The proposed experiment attaches
constraints to an existing supported Three.js deformation expression, changes
its designated parameters, and renders that same expression with the fitted
parameters. It does not establish a new inverse-kinematics, motion-editing or
automatic-differentiation algorithm.

## Closest prior work

- **Motion Editing with Spacetime Constraints, Gleicher, I3D 1997.** This already
  edits pre-existing motion through direct manipulation while preserving its
  original qualities. The solver considers the whole motion. Handles, temporal
  constraints and motion preservation therefore cannot be claimed as new.
  [Author's publication page](https://graphics.cs.wisc.edu/Papers/1997/Gle97a/).
  The underlying spacetime-constraint approach dates to
  [Witkin and Kass, SIGGRAPH 1988](https://publications.ri.cmu.edu/spacetime-constraints).

- **Direct Manipulation of Procedural Implicit Surfaces, Riso et al., SIGGRAPH
  Asia 2024.** This propagates viewport interactions back to procedural shape
  parameters through automatic differentiation, including constrained edits and
  nonlinear deformations. Its co-parameterization solves a harder tracking
  problem than attaching a handle to a known vertex of a fixed-topology mesh.
  Neither direct manipulation of procedural functions nor using AD to avoid
  manually moving their sliders is new.
  [Author project, paper and video](https://eliemichel.github.io/SdfManipulation).

- **Differentiable 3D CAD Programs for Bidirectional Editing, 2021 preprint.**
  A differentiable procedural language already supports geometry-to-parameter
  editing. This is prior art for maintaining one editable procedural model
  instead of separately transcribing its derivatives.
  [Primary paper](https://arxiv.org/abs/2110.01182).

- **Three.js IK implementations.** Three's `CCDIKSolver` already updates
  `SkinnedMesh` bones, and `IK-threejs` provides CCD/FABRIK implementations with
  joint constraints. A skeletal tentacle following a cursor would not establish
  a missing Three capability. The proposed input is instead an existing
  nonlinear vertex-deformation expression with no skeleton.
  [Three documentation](https://threejs.org/docs/pages/CCDIKSolver.html),
  [IK-threejs source](https://github.com/upf-gti/IK-threejs).

- **Slang.D, SIGGRAPH Asia 2023.** Existing rendering programs can already be
  differentiated with compiler-generated forward/reverse kernels, including
  much richer control flow than this prototype accepts. Native shader AD is an
  established technique; a JavaScript/TSL integration is the narrower boundary.
  [Primary publication](https://research.nvidia.com/labs/rtr/publication/bangaru2023slangd/).

## What would be useful here

The candidate contribution is a reusable adapter for native TSL node objects:
author the deformation once, designate point/time/parameter inputs, then bind
the same graph to rendering or constraint samples. `rebind.js` clones supported
operators and preserves shared subexpressions without rewriting the formula.
The parameter derivatives can then be generated by the existing restricted AD
compiler. No hand-authored Jacobian or per-deformation solver is needed.

This remains an integration hypothesis. A search did not identify a matching
native TSL editing library, but that is not evidence of being the first. The
work does not infer semantic controls, discover author intent, support arbitrary
AI-generated JavaScript, or make every shader editable. Authors must expose
adequate parameters and specify constraints. Some requested edits are infeasible
within the original parameterization and must be reported as unsatisfied.

## Decisive test

Use independently authored, structurally different nonlinear deformation graphs
with one unchanged adapter and solver. Verify actual rendered geometry after an
edit, including anchors, obstacle contact and motion preservation at additional
times. A sampled collision check is not a continuous-time guarantee. Compare
generated derivatives against central finite differences of the same forward
program under equivalent solver settings; report both quality and total work.

Success would show a reusable way to add constrained editing to existing Three
shader animations. A single tuned tentacle, hand-copied forward model, custom
solver for each fixture, or hidden between-sample penetration would not justify
that claim. No experiment result or speedup is asserted by this prior-art note.
